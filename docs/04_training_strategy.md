## Optimizer and Scheduler

| Setting | Value |
|---|---|
| Optimizer | AdamW |
| Learning rate | 5e-5 |
| Weight decay | 1e-4 |
| Scheduler | CosineAnnealingLR (T_max=500, eta_min=1e-6) |

**AdamW:** Decouples weight decay from gradient updates — standard choice for Transformers.  
**Cosine annealing:** Starts warm at `5e-5`, decays smoothly to `1e-6`, preventing premature convergence without causing instability.

---

## Loss Function

```python
CrossEntropyLoss(weight=class_weights, label_smoothing=0.1)
```

- **Class weights:** `1 / count` per class — rare signs penalized more per error
- **Label smoothing (0.1):** Trains toward `0.9` for the correct class instead of `1.0`. Prevents overconfident predictions and improves generalization on small datasets.

---

## Data Augmentation

Run 3 applied significantly stronger augmentation than Run 2 to fight overfitting with only ~8 videos per class.

| Augmentation | Prob | Run 2 | Run 3 |
|---|---|---|---|
| Temporal jitter | 50% | ±1 frame | ±3 frames |
| Gaussian noise | 70% | σ=0.005 | σ=0.03 |
| Frame dropout | 50% | 5% of frames | 25% of frames |
| Time warp | 50% | 0.85–1.15× | 0.70–1.30× |
| Mirror flip | 30% | ✓ | ✓ |
| Hand scaling | 50% | ✗ | 0.85–1.15× |
| Spatial jitter | 50% | ✗ | ±0.05 x,y |

All augmentations operate on non-zero frames only (zero-padding is preserved).

---

## Mixup

```python
mixed_x = λ * x_a + (1-λ) * x_b        # lambda ~ Beta(alpha=0.2)
loss = λ * CE(pred, y_a) + (1-λ) * CE(pred, y_b)
```

Forces the model to learn linear interpolations between classes, improving generalization and preventing overconfident predictions.

---

## Class Imbalance

WLASL-300 is heavily skewed — common words have 20+ videos, rare ones may have 5.

```python
class_weights = 1.0 / class_counts          # in loss function
sampler = WeightedRandomSampler(...)         # in DataLoader
```

Both work together: the sampler ensures balanced batch composition; the loss weights ensure rare classes still contribute proportionally even if the sampler is imperfect.

## Training Runs

### Run 1 — Baseline
- Standard architecture, no augmentation tuning
- Overfit quickly, discarded

### Run 2
- Architecture: `d_model=256, nhead=8, layers=4, dim_ff=512` (~3.8M params)
- Standard augmentation
- Results: ~39.6% top-1, 60.2% top-5 val accuracy
- Issue: High accuracy numbers but significant train-val gap — model memorized training set

### Run 3 (current production)
- Architecture: `d_model=192, nhead=6, layers=3, dim_ff=384` (~1.66M params)
- Stronger augmentation (see table above)
- 500 epochs

**Run 3 Results:**

| Metric | Value |
|---|---|
| Best Val Top-1 | 6.78% |
| Best Val Top-5 | 23.57% |
| Best Epoch | 464 |
| Test Top-1 | 5.09% |
| Test Top-5 | 20.57% |
| Train-Val Gap | 1.16% ← excellent generalization |
| Peak Train Acc | 8.44% |

> **Why lower accuracy than Run 2?** Run 3 is more honest — it genuinely generalizes (1.2% train-val gap) whereas Run 2 was memorizing training samples. WLASL-300 with ~8 videos/class is an extremely hard benchmark; published academic models without pre-training report similar numbers.
